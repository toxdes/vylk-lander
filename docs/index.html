VYLK / Docs

A small notebook
you can run yourself.

VYLK is a lightweight Markdown editor for one person's notes, across their devices. It has live preview, offline-first sync, and optional end-to-end encryption. This guide covers the first run, daily use, and deployment.

Start here

VYLK runs on a computer you control and opens in a browser. Linux packages are the easiest installation. Docker is convenient for a server, while the standalone binary and source build work when you want a smaller or more manual setup.

Choose an installation method, start VYLK, then open localhost:8080. Sign in with the password you configured.

By default, Markdown notes are stored in ./notes and the SQLite database is ./vylk.db, relative to the directory where VYLK starts. Keep the process running while you use the app.

Install VYLK

Pick your computer, then choose the simplest way to install it. Each panel also shows the short update path for that method.

Ubuntu or Debian

Add the shared Toxdes repository once, then install VYLK.

sudo apt update && sudo apt install -y ca-certificates curl gnupg && curl -fsSL https://packages.toxdes.com/apt/pubkey.gpg | sudo gpg --dearmor --yes -o /usr/share/keyrings/toxdes-archive-keyring.gpg && echo "deb [signed-by=/usr/share/keyrings/toxdes-archive-keyring.gpg] https://packages.toxdes.com/apt stable main" | sudo tee /etc/apt/sources.list.d/toxdes.list && sudo apt update
sudo apt install vylk
VYLK_PASSWORD='replace-with-your-password' vylk

Update: run sudo apt update && sudo apt upgrade vylk, then restart VYLK.

Fedora

Add the shared Toxdes repository once, then install VYLK.

printf '%s\n' '[toxdes]' 'name=Toxdes' 'baseurl=https://packages.toxdes.com/rpm' 'enabled=1' 'gpgcheck=1' 'repo_gpgcheck=1' 'gpgkey=https://packages.toxdes.com/rpm/pubkey.gpg' | sudo tee /etc/yum.repos.d/toxdes.repo
sudo dnf install vylk
VYLK_PASSWORD='replace-with-your-password' vylk

Update: run sudo dnf upgrade vylk, then restart VYLK.

Docker

The image supports Linux AMD64 and ARM64. The named volume keeps your notes and database.

docker run -d --name vylk -p 127.0.0.1:8080:8080 -e VYLK_PASSWORD='replace-with-your-password' -v vylk-data:/data toxdes/vylk:{version}

Open localhost:8080 after the container starts.

Update: pull the new image, remove the container, then run the same command again with the volume unchanged.

Use your other devices

VYLK listens on port 8080 by default. For an unencrypted instance, you can open the host computer's local IP address on a trusted network; the host firewall must allow the connection. Plain HTTP does not protect your password or notes in transit.

For encrypted notes, use HTTPS even on your local network. HTTP on a LAN address such as http://192.168.1.10:8080 is not a secure browser context and cannot unlock the vault. HTTP on localhost or a loopback address works on the machine running VYLK. Read the encryption setup requirements.

Put VYLK behind an HTTPS reverse proxy with a certificate trusted by each device. VYLK does not issue certificates or serve HTTPS itself. HTTPS is also needed for service workers and PWA installation, except on localhost. The Docker examples bind to localhost; expose the service through your reverse proxy for other devices.

Sign in online once on each device before relying on offline access. Keep password protection enabled and use VYLK_TRUST_PROXY=1 only when a trusted proxy supplies the forwarding headers.

Configuration

VYLK uses environment variables. The server password also accepts VYLK_PASSWORD_FILE=/run/secrets/vylk_password for Docker and other secret managers. Enable E2EE in the app; its passphrase and recovery key are not server environment variables.

VYLK configuration variables
VariableDefaultPurpose
VYLK_PASSWORDnoneRequired before E2EE is enabled. After conversion, the vault passphrase or recovery key signs you in; keeping this server password enables a destructive new-vault reset, not recovery of old notes.
VYLK_PASSWORD_FILEunsetRead the initial server password from a secret file instead of placing it directly in an environment variable.
PORT8080HTTP listen port.
VYLK_DIR./notesDirectory containing plaintext Markdown files or encrypted vault note files.
VYLK_DB./vylk.dbSQLite database path for metadata, sync state, and encrypted vault key wrappers. Back it up together with the notes directory.
VYLK_APP_NAMEVYLKServer-wide app and PWA display name. Restart after changing it.
VYLK_TRUST_PROXYunsetSet to 1 only behind a trusted TLS-terminating proxy.
VYLK_REQUIRE_STRONG_PASSWORDSfalseSet to true or 1 to require a strong server password and tell browsers to enforce strong vault passphrases.
VYLK_DISABLE_VAULT_CHANGESfalseSet to true or 1 for a shared demo. The API rejects encryption setup, passphrase/recovery-key changes, vault reset, and device revocation. Notes and sign-in still work; this does not turn off an existing encrypted vault.
VYLK_NO_BROWSERunsetSet to 1, or use --no-browser, to skip best-effort browser opening on startup.
ARTIFICIAL_RTT_DELAY_MS0Development-only request delay. Do not enable it in production.

A practical local setup

VYLK_PASSWORD=change-this PORT=8080 VYLK_DIR=./notes VYLK_DB=./vylk.db ./vylk

Features

Markdown and live preview

Write Markdown, use the formatting toolbar, and see the rendered result beside the editor. Cursor-position highlighting connects source text to the preview.

Focused editing

Use a resizable split view, editor-only or preview-only view, or Zen mode for a quiet writing page. Caret-following scroll eases as you type and respects reduced motion.

Interactive preview

Check tasks, edit Markdown blocks, and drag blocks to rearrange them without leaving the preview. On mobile, selected blocks use a fixed action tray.

Configurable interface

Choose themes, fonts, content widths, autosave, toolbar and save-button visibility, and your starting view. Appearance's Reduce motion setting can follow your system, always reduce motion, or never reduce motion.

Keyboard shortcuts

In the editor, use Ctrl+1 for write view, Ctrl+2 for preview, Ctrl+3 for split view, and Ctrl+4 for Zen. On macOS, use Command instead of Ctrl. Customize bindings in Preferences → Shortcuts; the default sequence prefix is Ctrl+E.

Offline-first notes

After the first online sign-in, the installed app caches its shell and notes, stores edits in IndexedDB, and synchronizes when the connection returns.

Your devices

Use desktop and mobile browsers or install the PWA. Encryption unlocks are remembered across tabs and refreshes. Preferences lists browser profiles so you can sign out another device.

End-to-end encryption

Optionally encrypt note titles, tags, bodies, and offline edits on your device before storage or sync. A passphrase or 24-word recovery key unlocks your vault. Understand setup and recovery.

Storage you control

Without E2EE, notes are Markdown files with SQLite metadata. With E2EE, the server stores encrypted note bodies and encrypted titles/tags. Back up the database and notes directory together.

First-run defaults

New accounts open notes in write view, with interactive preview and the formatting toolbar enabled. Automatic saving is on and the manual Save button is hidden. Zen uses Inter at 125%, with the title, word count, and view switcher visible. Saved preferences are preserved when you upgrade.

End-to-end encryption

E2EE is optional. Your browser encrypts note titles, tags, bodies, and pending offline edits before sending them to the server or storing them locally. The server stores ciphertext and wrapped keys; it never receives your vault passphrase or recovery words.

HTTPS first

Open VYLK over HTTPS, or use http://localhost:8080 on the machine running it. Your browser must report a secure context for its cryptography APIs. Plain HTTP on a LAN IP does not qualify, even on a network you trust.

Can't sign in to an encrypted instance?

If the login screen says encryption requires HTTPS, use the instance's HTTPS address with a trusted certificate. On the host computer, localhost also works. Existing signed-in pages opened in an insecure context are returned to the login screen with this notice; bypassing the notice does not enable browser cryptography.

Enable encryption

  1. Back up VYLK_DB and VYLK_DIR together. Sign in with your current server password and open Preferences → Encryption.
  2. Choose a vault passphrase. Download or write down the numbered 24-word recovery key and store it somewhere safe, separate from the server.
  3. Confirm all 24 words one at a time while the original list is hidden, then acknowledge the warning about losing access. Bulk pasting is intentionally unavailable to encourage keeping a separate copy.
  4. Keep the page open while VYLK encrypts and verifies existing notes, converts local offline edits, and switches the server to encrypted storage. Note writes pause during conversion.
  5. After conversion, restart the server to release plaintext still in the old process's memory. Update and unlock your other devices to convert their local caches too.

If conversion is interrupted, reopen setup with the original server password, vault passphrase, and recovery key to resume. A device you have not reopened may still contain its earlier plaintext cache.

Passphrase and recovery key

After conversion, your vault passphrase or recovery key signs you in and unlocks notes. The old VYLK_PASSWORD no longer unlocks the encrypted vault. Recovery downloads are named vylk-recovery-key-YYYYMMDDHHMM.txt; anyone with that key can unlock the vault, so treat the file like a password.

In Preferences → Encryption, verify your current passphrase or recovery key before choosing a new passphrase or replacing the recovery key. Changing the passphrase offers Sign out other devices, enabled by default. Replacing the recovery key revokes other sessions. The current browser signs in again automatically.

Keep a separate recovery copy.

If you lose both the passphrase and recovery key, VYLK cannot recover your encrypted notes. Backups alone cannot unlock them. Keeping VYLK_PASSWORD configured offers a destructive reset to a new empty vault, not access to the old notes. Old ciphertext is archived on the server for 30 days, but still needs its original secret to decrypt.

Remembered browsers and devices

Signing in remembers a non-extractable browser key so other tabs, refreshes, app updates, and later visits do not require another unlock while server access remains valid. Anyone using that browser profile can read your cached notes. Sign out on shared devices: this forgets the remembered key but retains encrypted pending edits for your next unlock.

Preferences → Account → Devices groups tabs from one browser profile as one device. Signing out a device revokes its server sessions. Offline devices detect revocation when they reconnect; revocation cannot erase their cached notes or keys they already possess.

What encryption does and does not cover

Argon2id derives a wrapping key from the passphrase; a random vault key encrypts notes with AES-256-GCM. The server still sees note IDs, revisions, timestamps, pin state, preferences, and sync activity. Search, tag filtering, and conflict resolution run on unlocked devices.

Use a trusted deployment and HTTPS. A compromised server can replace the web app and steal secrets at unlock, or use a remembered key on your next visit. Encryption does not detect a server replaying older valid ciphertext. Changing a passphrase or recovery key rewraps the same vault key; it does not revoke a key or old wrapped-key copy that has already been stolen.

A shared demo can keep the encryption UI explorable while rejecting all vault changes at the API with VYLK_DISABLE_VAULT_CHANGES=true. That flag freezes vault configuration, not note editing, and does not disable an already-encrypted vault. Startup refuses it during an unfinished encryption migration.

Backups and safety

Stop VYLK before making a matched copy of VYLK_DB and VYLK_DIR, or use a consistent backup method that captures them together. For encrypted notes, keep the passphrase or recovery key separately. Restarting with the same matched data and valid credentials resumes the instance; neither the database nor notes directory alone is a complete backup.

Enabling E2EE removes the active plaintext storage and its temporary conversion backup, but cannot erase old external backups, SQLite migration snapshots, unopened browser caches, filesystem snapshots, or freed disk blocks. Review those copies under your backup policy.

Upgrading from server-side file encryption

The older server-side encryption feature and its environment variables have been removed. Export those notes as plaintext using the previous VYLK version before upgrading, then enable E2EE in the app if desired. Removed settings and recognized encrypted files stop startup safely. The oldest ciphertext format has no identifying header: removing its settings does not decrypt the files.

Migration backups

Before a pending database migration, VYLK creates a consistent SQLite snapshot beside the database. The three newest *.pre-migration-*.db snapshots are retained. Keep roughly one extra database-sized block of free space.

Offline use and sync

Sign in once while online, then install VYLK as a PWA if your browser supports it. You can reopen it without a connection, edit or delete notes, and continue working. Changes wait in the browser's IndexedDB and synchronize when connectivity returns.

While the app is open, an authenticated event stream watches for changes. A 25-second heartbeat drives the Online or Offline indicator. A missing heartbeat for 70 seconds is treated as offline; reconnection performs a full cache reconciliation before replaying local work.

If two devices change the same note, VYLK attempts a three-way merge. Non-overlapping line edits and one-sided title or tag changes merge automatically. Ambiguous overlaps open a conflict resolver that preserves both versions and lets you edit the result.

Sign-out retains cached notes and pending edits for your next sign-in. Without E2EE, that browser storage is plaintext; signing out does not erase it. With E2EE, local notes and queued edits are encrypted, and sign-out forgets the remembered unlock key. When the server is unavailable, the current device's Sign out action locks this browser locally but cannot revoke its server session.

The status badge says Saving while changes await server acknowledgement and Saved after they reach the server. Offline means edits remain on this device until reconnection. Do not clear browser storage while you have pending work.

If the server database is replaced, VYLK pauses sync and asks you to choose Keep changes or Switch. Keep changes preserves local work; restore the previous matched database and notes directory, then reload. Switch permanently discards this browser's cached notes and pending edits, loads the replacement instance, and asks you to sign in again. Restoring an older backup of the same database keeps its identity; this check is not rollback detection.

Build and test

Build one local binary with the version embedded from VERSION:

go build -trimpath -ldflags="-s -w -X vylk/internal/server.version=$(cat VERSION)" -o vylk ./cmd/vylk

Build all supported binaries and platform archives with:

./build.py

Build the Linux packages and archives with Yesb:

./yesb/build_all.py

Use the Go version declared in go.mod and Bun for frontend tooling. Install dependencies, then run the Go, frontend, and browser suites. Browser tests require Chrome, or CHROME_PATH pointing to a compatible binary.

bun ci
go test ./...
go tool staticcheck ./...
bun run test:frontend
bun run test:browser
